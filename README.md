# feature-recognition-effect-toward-utterance

相手の特徴認識が初に与える影響の調査に関する研究

---

## Ryu: Japanese conversational adaptation research

Code for two linked pieces of research on how Japanese speakers adapt their speech to a
conversation partner (gender and age), and whether an LLM can reproduce that behaviour.

| Folder | What it is |
|---|---|
| [Dataset_Analysis/](Dataset_Analysis/) | Corpus analysis of CEJC and NUCC (Meidai): sentence-final particles (SFP), first-person pronouns, F0, speaking tempo, fillers, mora counts; plus comparison of LLM-converted speech. |
| [System_implement/LLM_Response/](System_implement/LLM_Response/) | Gemini persona-vs-persona chat generator whose SFP and pronoun usage is steered by gender/age profiles, plus a counter that classifies the SFPs actually produced. |
| [System_implement/jvs_to_esd.py](System_implement/jvs_to_esd.py) | Helper that converts a JVS speaker into the Style-Bert-VITS2 training format. |

## What is NOT in this repo

The repo holds code, small data files and plots only. These are kept out on purpose
(see [.gitignore](.gitignore)):

- `Corpus/` (CEJC, NUCC, BTSJ, JVS): the raw corpora are large and have licences that restrict redistribution. **You must obtain them yourself.**
- `Research/` and `System_implement/Style-Bert-VITS2/`: separate projects and model weights.
- Virtual environments (`.venv*`), caches, logs.
- Anything under `Dataset_Analysis/**/output/` **except the plots** (`.png` / `.svg`). The CSV/HTML/JSON results are regenerated by running the scripts.
- `Dataset_Analysis/CEJC_Analyse/cleaned-data/`, `CEJC_iiyodomi/utterances_with_filler*.csv`, `LLM_SFP_comparison/*_result/`: they contain corpus utterances.
- `System_implement/LLM_Response/outputs/`: generated chats, ignored while experiments are still running. Final runs can be added with `git add -f`.

## Setup

Python 3.12. Each project has its own requirements file:

```bash
# Dataset_Analysis
cd Dataset_Analysis
uv venv .venv && uv pip install -r requirements.txt     # or: python -m venv .venv && pip install -r requirements.txt

# LLM_Response
cd System_implement/LLM_Response
uv venv ../.venv-llm-response && uv pip install -r requirements.txt
# requirements-lock.txt is the exact full freeze if you need to reproduce versions
```

`torch` / `transformers` are only needed for `LLM_SFP_comparison` (local Swallow and calm3 models).
Install the `torch` build that matches your CUDA version.

**Paths are hard-coded.** Most scripts use absolute paths such as `/home/ryuu/Ryu/Corpus/CEJC` and
`/home/ryuu/Ryu/Corpus/nucc/Himawari_nucc/Himawari_meidai`. Either place the project and corpora at
`/home/ryuu/Ryu/`, or edit the path constants near the top of each script.

## Dataset_Analysis

Each subfolder is one analysis. Scripts write to an `output/` folder next to them.

| Folder | Script(s) | Analysis |
|---|---|---|
| `CEJC_Analyse/` | `data_cleaner.py`, `speaker_log_mapping.py`, `analyzer.py` | Clean transcripts, map speakers to conversations (valid/excluded), count mora per speaker and gender pair. Other scripts depend on the cleaned data and mapping. |
| `CEJC_SFP_Analyze/` | `SFP_counter.py`, `SFP_counter_AI.py`, `SFP_speaker_shift.py` | Count SFP in CEJC; classify them into gender-intensity buckets with an LLM; plot how one speaker's SFP changes between conversations. |
| `CEJC_pronoun/` | `CEJC_pronoun_analysis.py` | First-person pronoun usage by speaker and partner. |
| `CEJC_F0_Analyze/` | `CEJC_F0.py`, `CEJC_DynamicRange.py` | ΔF0 and F0 dynamic range adaptation toward the partner. |
| `CEJC_tempo/` | `CEJC_tempo.py` | ΔTempo (speaking rate) adaptation. |
| `CEJC_iiyodomi/` | `CEJC_iiyodomi_analysis.py`, `..._relation_analysis.py`, `..._graphs.py` | Filler (iiyodomi) frequency by gender, age and relationship. Run in this order. |
| `nucc_analysis/` | `nucc_SFP_analysis.py`, `nucc_pronoun_analysis.py` | Same SFP and pronoun analyses on the Meidai/NUCC corpus. |
| `LLM_SFP_comparison/` | `gemini_test.py`, `Llama-3-Swallow.py`, `calm3-22b-chat.py` | Convert CEJC utterances to a target speaker profile with different LLMs and compare the resulting SFP. |
| `BTSJ_Analysis/` | `BTSJ_SFP.py` | Placeholder (empty file). |

Several scripts cache expensive work (`*_cache.json`, `ai_cache/`) so an interrupted run can resume.
Delete the cache to force a full re-run.

## LLM_Response

Two Gemini-driven characters chat; each turn, the target SFP/pronoun/address-term category is
chosen from the taxonomies in [data/](System_implement/LLM_Response/data/) and given to the model.

```bash
export GENAI_API_KEY=...        # required, never commit it
cd System_implement/LLM_Response/src

# one pairing, 30 turns
python Response_All_AI_weight_random.py --mode generate --age-a 20s --gender-a male --age-b 20s --gender-b female --turns 30
# same, plus a live per-turn SFP classification
python Response_All_AI_weight_random.py --mode debug --age-a 20s --gender-a male --age-b 20s --gender-b female
# re-classify and chart saved chats across runs
python Response_All_AI_weight_random.py --mode counter
```

- `Response_All_AI_weight_random.py` is the latest version (weighted-random category, then intensity). Run with `--help` for all flags; omit the age/gender flags to sweep.
- The other `Response*.py` files are earlier iterations kept for reference (`_v1`, `_no_random`, `_RatioInPrompt`, `Response.py`, `Response_v1_fixBucket.py`).
- `data/`: character settings, persona presets, and the SFP / pronoun / address-term buckets (`*_kaExclude*` variants drop the particle か).
- Output goes to `outputs/chat_logs/<timestamp>/` (chats) and `outputs/sfp_ai_output/` (classification and charts).

## Notes

- The Gemini model name (`gemini-3.5-flash-lite`) is hard-coded in the scripts; change it there if it is retired.
- Mixing results from different taxonomy files (`SFP_Bucket_by_gender*.json`) will change the numbers; check which file a script loads before comparing runs.
